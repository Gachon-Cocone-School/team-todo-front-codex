# Team Todo 기능 계획과 구현 상태

## 목적과 범위

Next.js로 TODO 백엔드에 연결되는 팀 작업 앱을 제공합니다. 한 앱에서 `Productivity`와 `Warm` 두 테마를 지원하며, 사용자는 별도의 설정 화면에서 테마를 선택합니다.

필수 화면은 TODO 목록, TODO 상세, 설정입니다. TODO 생성·조회·수정·삭제, 백엔드 목록 필터와 페이지 이동을 지원합니다. 인증과 관리 화면은 제공하지 않습니다. 앱에 접속하면 TODO 목록이 먼저 표시됩니다.

## 백엔드 API

README와 백엔드의 기획 문서·라우터를 확인하고, 2026-10-08에 로컬 OpenAPI 문서(`http://127.0.0.1:8000/openapi.json`)와 대조했습니다.

- 기본 경로: `/api/v1/todos`
- 목록 조회 `GET`, 생성 `POST`, 상세 조회 `GET`, 부분 수정 `PATCH`, 삭제 `DELETE`
- 목록 필터: 상태, 담당자, 우선순위, 마감일 범위, 태그
- API 페이지네이션: `limit` 기본 50·최대 100, `offset` 기본 0
- TODO 필드: 제목, 설명, 담당자, 마감일, 우선순위, 상태, 태그, 생성·수정 시각
- 상태: `TODO`, `IN_PROGRESS`, `DONE`
- 우선순위: `LOW`, `MEDIUM`, `HIGH`
- 인증은 필요하지 않습니다.

| 메서드   | 경로                      | 기능                        | 성공 응답      |
| -------- | ------------------------- | --------------------------- | -------------- |
| `GET`    | `/api/v1/todos`           | 필터·페이지네이션 목록 조회 | `200 TodoPage` |
| `POST`   | `/api/v1/todos`           | TODO 생성                   | `201 TodoRead` |
| `GET`    | `/api/v1/todos/{todo_id}` | TODO 상세 조회              | `200 TodoRead` |
| `PATCH`  | `/api/v1/todos/{todo_id}` | TODO 일부 수정              | `200 TodoRead` |
| `DELETE` | `/api/v1/todos/{todo_id}` | TODO 삭제                   | `204`          |

상세 응답에는 `id`, `title`, `description`, `assignee`, `due_date`, `priority`, `status`, `tags`, `created_at`, `updated_at`이 포함됩니다.

## 사용자 흐름

1. 앱에 접속하면 저장된 테마가 적용된 TODO 목록을 확인합니다.
2. 상태, 담당자, 우선순위, 마감일 범위, 태그로 목록을 필터링하고 페이지를 이동합니다.
3. 목록에서 TODO를 만들거나 항목을 선택해 상세 내용을 확인합니다.
4. 상세 화면에서 TODO를 수정하거나 삭제합니다.
5. 설정 화면에서 테마를 바꾸면 선택이 브라우저에 저장되고 앱 전체에 적용됩니다.

## 기술 구성

- Next.js App Router를 사용합니다.
- 브라우저 요청은 Next.js 프록시(`/api/backend/todos`)를 거쳐 백엔드 `/api/v1/todos`로 전달합니다.
- 백엔드 주소는 `.env.local`의 `API_BASE_URL`에서 읽습니다.
- 생성은 목록 화면에서 시작하고, 수정과 삭제는 상세 화면에서 제공합니다.
- 인증, 댓글, 별도 관리 화면은 범위에 포함하지 않습니다.
